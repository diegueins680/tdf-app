# Atomic contact and Live Session creation

The contact API now requires an actor-scoped Idempotency-Key. Current web forms and the mobile contact form retain it after a failed response or a field edit. The database compares the accepted payload and returns a conflict instead of creating another contact. Completing or explicitly abandoning a form starts a new attempt. Older applications and import/API clients without a key receive a refresh/update error; they must send a stable 16–128 character ASCII request ID per source operation. Never derive person identity from names or contact details. Separate operations may legitimately create separate people with identical fields.

Live Session intake requires the same request header and saves the intake, newly supplied contacts, musician relationships, songs, and request receipt in one database transaction. Concurrent retries serialize by actor and request key. A retry with the same accepted payload has no additional database effects; a changed accepted payload returns 409. The web form saves the submission key with its owner-scoped draft. New musicians are no longer pre-created by the browser.

Email alone never selects an existing musician. Explicit contact IDs require the actor's existing CRM access or their own identity. Intake does not create credentials or grant artist roles. Shared contact details remain valid for separate people. Existing contact information is not overwritten: submitted notes, Instagram, and phone details stay with the intake for review.

Rider files use actor/request/content-derived paths in the existing upload directory. An unchanged retry verifies and reuses the stored bytes. A failed transaction can leave an unreferenced file, which is recoverable on retry; a differing or partial existing file blocks the request for operator review rather than overwriting evidence. This change does not add storage replication beyond the application's existing upload deployment.

Migration 109 adds private request receipts and an archived-actor reference guard. Its rollback is permitted only before any receipt exists. After use, application rollback must preserve the table and replay protections. Identity merge rollback remains operation-specific as documented in reconciliation.md.

Validation runner: `sh scripts/test-live-intake-identity.sh`, using an isolated local PostgreSQL server. It creates and removes its own disposable database and checks concurrent requests, actor scope, false email matches, explicit authorization, partial failure rollback, archived references, rider reuse, and receipt-preserving schema rollback. CI runs this alongside the existing identity reconciliation tests. The migration also needs the established staging/restored-production rehearsal before deployment.

Native rollout remains subject to the repository's physical-device Google sign-in release gate because its companion includes the provider changes. No native publication or production deployment is claimed by this document.

The bundled `tdf-hq/scripts/create_artists_from_list.sh` now uses a stable import namespace and source-row key, and requires a reviewed JSON array of entity-type booleans via `ARTIST_ENTITY_TYPES_FILE`. Keep the namespace and row order on retries. Do not infer person/band types from names. It stops on HTTP errors. Profile creation must be reviewed in the existing administrative artist directory: the legacy profile upsert cannot safely preserve later edits on retry, so the batch no longer invokes it. This importer does not infer links to historical imports; review existing records before authorizing a new source operation.

Accepted intake receipts are checked before mutable catalog publication state. Replays still verify the saved rider bytes, restore a missing local file from the identical submitted content, and reject conflicting bytes without altering them. A physical iOS device is unavailable, as confirmed by the operator; native release validation remains blocked. Older native contact forms without request keys must use the updated web form until an approved native release is available.
