# PlusCal source/translation integrity contract

Scope: EO-057's verification artifacts, not a new booking implementation. The existing
`ReservationRace` model, invariants, constants, atomicity and fairness assumptions remain
unchanged. This executable tooling contract does not require a new domain state machine.

## Diagnosis (2026-09-15)

PR 17 reported TLC's warning that the `ReservationRace` TLA+ translation had changed since
translation. Regenerating a disposable copy using the checksum-pinned TLA+ tools 1.7.2 JAR
and `pcal.trans -nocfg -unixEOL` reproduced exactly two missing trailing spaces in the
committed generated block, on its wrapped `UNCHANGED` lists. Neither the algorithm nor
the TLA+ expressions differed. The generator kept checksums `14601121` / `6057351e`.
This is evidence of formatting drift in this file, not proof that warnings are harmless.

Regeneration with the explicit additional option `-lineWidth 120` keeps both lists on
single lines and emits no trailing whitespace for this model. The generated TLA checksum
becomes `aaece465`; the algorithm checksum remains `14601121`. The committed file matches
that generated output byte for byte. No manual checksum calculation or warning suppression
is used. Wider wrapping does not change the two expressions or any model configuration.

## Executable obligations

| ID | Contract | Enforcement / evidence |
|---|---|---|
| PC-01 | Translate with the pinned JAR and fixed, documented options | `pinnedToolchain`, SHA-256 verification, `translatorArgs`; missing/fake JAR tests |
| PC-02 | A successful check means the entire committed file equals regenerated bytes, including checksums and whitespace | `verifyTranslation`; algorithm-only, translation-only, both checksum, whitespace and original-defect mutations |
| PC-03 | Verification never writes the source or adjacent `.old`/`.cfg` files | Per-invocation temporary copy, `-nocfg`, cleanup in `finally`; accepted/rejected fixture preservation tests |
| PC-04 | Translation failure, absent Java, successful process without translation output, malformed/missing/duplicate markers and unsupported CLI flags fail closed | Process exit/output checks, 30-second timeout, pair validation; failure tests |
| PC-05 | ReservationRace cannot disappear from the gate; additional PlusCal artifacts are discovered | Required file plus recursive `.tla` scan; new-model drift and removed-pair tests |
| PC-06 | Integrity and its regression tests run before TLC and cannot silently be skipped in CI | Existing formal runner, explicit Node 22 CI setup, PR/main path triggers; wiring tests |

The checker takes no CLI model override, update, ignore-whitespace or skip switch. Its
exported functions accept temporary fixture paths for tests; the production CLI fixes the
repository model directory and validates the toolchain. Tests require the real pinned JAR;
missing tooling fails instead of producing skipped or mocked translator results.

## Reproduction and regeneration

With `JAVA_BIN` and `TLA2TOOLS_JAR` pointing to the runtime and pinned JAR:

```bash
npm run verify:event-operations:pluscal
npm run test:event-operations-pluscal
```

To intentionally update an algorithm, regenerate its translation with:

```bash
"$JAVA_BIN" -cp "$TLA2TOOLS_JAR" pcal.trans -nocfg -unixEOL -lineWidth 120 \
  formal/event-operations/ReservationRace.tla
```

Unlike the verification command, intentional regeneration writes the target and may create
an adjacent `.old` backup. Review the complete diff; do not manually edit the generated
block or strip its whitespace. Re-run the integrity gate, mutation tests and complete
`verify:event-operations:formal` command with `ALLOY_JAR` configured before implementation.
If future generated output contains significant-for-checksum trailing whitespace, review
the generator options/output policy explicitly instead of normalizing inside the checker.

## Limits and security

This checks reproducibility with a trusted pinned translator, not translator correctness,
formal refinement into SQL, cryptographic authenticity of model authors, or unbounded
reservation safety. Arbitrary handwritten helper/invariant edits still require semantic
review and TLC/Alloy checks. Both model and generated block can change together legitimately;
integrity is not a substitute for invariant review. The scanner is a repository convention,
not an adversarial PlusCal parser. CI uses a fixed checkout; source comparison catches changes
during each translation but does not lock the worktree through subsequent TLC execution.

Each existing reservation configuration still contains two overlapping requests and one
exclusive resource, with confirmation atomic and no new fairness condition. Capacity,
multi-resource locking, travel buffers and actual concurrent SQL/HTTP booking behavior remain
the separate, incomplete integration obligations in the traceability matrix.

No application, database, permission, financial, provider, API, generated-client, mobile or
deployment setting changes. Cleanup targets only directories created by this invocation.
Rollback is a reviewed revert of this tooling change; that restores the known warning and
removes the integrity gate, so it is not a release-readiness workaround.
