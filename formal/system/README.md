## Shared glossary and composition boundary

- Principal: authenticated credential identity acting as a Party. Email/contact equality is not
  identity proof. Public artist/profile IDs, Party IDs, entity ownership and membership are distinct.
- Ownership/role/grant: domain-specific authority; a public profession, follow, purchase or RSVP
  never implicitly supplies administrative authority. Revalidate at the actual operation boundary.
- Money: `(currency, integer minor units)`. Capture/refund are financial evidence transitions;
  fulfillment, settlement and payout have independent states and authority.
- Time: persisted UTC instant; explicit IANA zone for presentation. Resource intervals are
  half-open; rental date ranges are inclusive. These are distinct units, not interchangeable ranges.
- Revision/idempotency: record version authorizes a transition; request key binds a retry to its
  original payload. Neither grants authority after revocation. Network delivery is not exactly once.
- Verified: always qualified by artifact, method, assumptions and revision. A bounded model result,
  test pass, deployment health or source hash alone is not whole-system conformance.

Composition currently established: recognized capture/refund admission expressions and their
numeric update are analyzed together over all 64-bit values with nonnegative current/limit. The
outer `transitionPayment` checks nonnegative lifecycle fields; capture selects its ceiling from
authorized/total fields and refund from captured. This caller argument is manually inspected, not
a proved whole-Haskell call graph. The SQL adapter locks the row, invokes that function and writes
its result; SQL constraints independently reject negative/out-of-range counters. SQL transaction,
authentication, serialization and provider evidence are **not** discharged by the arithmetic proof.

The existing Alloy integrated event scenario checks simultaneous relational constraints and
non-vacuity in its stated finite scope. It does not compose all social, commerce, mobile and
operational models. Pairwise/domain passes do not close global obligation SYS-GAP-02.

## Reproduction and contribution

```sh
python3 scripts/specification-inventory.py --check
python3 -m venv /tmp/tdf-verification-venv
/tmp/tdf-verification-venv/bin/pip install -r formal/system/requirements-verification.txt
/tmp/tdf-verification-venv/bin/python scripts/verify-payment-arithmetic.py
/tmp/tdf-verification-venv/bin/python scripts/test-payment-arithmetic-verifier.py
node --test scripts/__tests__/verification-evidence.test.mjs
cd tdf-hq
stack exec -- runghc -isrc test/PaymentArithmeticProbe.hs
stack test
```

For TLC/Alloy set `JAVA_BIN`, `TLA2TOOLS_JAR`, `ALLOY_JAR` to the pinned tools documented in
`formal/event-operations/README.md`, then run from root:

```sh
node scripts/verify-system-evidence.mjs --output /tmp/tdf-verification-NEW-RUN
```

Output must be a new directory. Sources, gitlink, tools, exit status and logs are retained;
source drift or missing completion evidence fails. A revision change must be revalidated before
release even when a source digest happens to match. Never count a timeout/unknown as proof.
The first mixed integer/bitvector solver attempt timed out; the equivalent exact 65-bit sum
encoding avoids that search issue without narrowing 64-bit inputs. An exploratory TLC run was
invalidated by editing its runner during execution; no pass is attributed to it.

When adding/changing a requirement: retain provenance and approval state, update the domain
contract and explicit trace/gap, regenerate/review the inventory, rerun affected obligations,
and record exact source/tool identities. New models require success reachability and meaningful
negative controls. Changes to the recognized payment function shapes fail the solver checker
until its correspondence is reviewed. CI runs inventory/admission/SMT and existing bounded
models on all PRs/main plus weekly; backend CI runs the actual-module oracle and Hspec suite.

See [payment-arithmetic.md](payment-arithmetic.md) for the exact proof boundary and trusted base.
