# Native test resolver lock — SYS-NATIVE-RESOLVER-001

The root CI recipe installs with `npm ci`; Safe Install disables installation
scripts. Its existing lock declared 19 exact optional `unrs-resolver@1.11.1`
bindings but recorded none of their package entries. A pristine macOS install
completed successfully, then loading the required Jest resolver with runtime
downloads disabled failed with `Cannot find native binding`. Manual copies or
the resolver's lazy installer made results depend on extra setup after install.

The replacement records were generated in a disposable workspace with the
tracked `.npmrc`: temporarily pin the same resolver directly, refresh its lock
node, restore the original manifest/root entry, and recheck with npm's lock-only
install. The resulting diff adds 24 optional records and changes no old records.
This is a repair of this inherited lock, not a claim that current npm still has
the historical [optional dependency bug](https://github.com/npm/cli/issues/4828).
The [npm ci contract](https://docs.npmjs.com/cli/v11/commands/npm-ci/) remains the
installation authority.

The correction must preserve all existing lock records and package manifests,
restore the missing optional records generated by npm for the existing pinned
resolver, and keep these properties:

- The installed resolver version and complete optional declaration set equal
  the locked resolver. Every declared binding has the exact version, HTTPS
  archive location, SHA512 integrity and optional designation in the lock.
- Canonical UI checks and Safe Install disable the resolver's runtime package
  downloader. UI qualification loads the resolver in a fresh process before
  running its checks, without native-path or forced-WASI overrides.
- A missing or mismatched lock record fails the repository gate. A missing host
  binary fails the actual load probe; restoring that same binary restores it.

`scripts/check-native-resolver-lock.mjs` and its unit controls enforce the narrow
lock contract. `quality-ui.sh` uses its actual native load probe, while
`quality-repo.sh` runs the structural checks and negative fixtures. The existing
Safe Install lane retains disabled install scripts and audit thresholds.

Assurance is TESTED, not PROVEN. Direct optional bindings are checked; this is
not a complete npm transitive graph, supply-chain or reproducible-build proof.
Archive trust remains npm's SRI and registry trust assumption. Other platform
records are checked structurally; actual startup is established only for the
documented local/CI platform executions. This changes test-tool dependencies,
not product behavior or the separate browser/worker contract.
