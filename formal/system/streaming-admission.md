# Native streaming containment — MEDIA-STREAM-001

The product owner approved unavailable broadcasting during repair on 2026-10-05.
Native radio and event broadcast creation are unavailable (`503`). Setting
`RADIO_PUBLIC_BASE`, `RADIO_INGEST_BASE` and `RADIO_WHIP_BASE` cannot enable them.
Authentication and request decoding remain active; the event route also preserves
visible-event, lineup, follower and caller-identity checks. Neither handler creates
a database record or contacts a provider. Ordinary external-station listening is
retained, subject to the conservative legacy quarantine below.

The previous implementation invented absent endpoint bases (including historical
Fly addresses), inserted an active radio stream or `status=live` event record, and
used the same UUID for playback paths and publishing authority. Event list and
viewer-heartbeat DTOs included ingest/WHIP URLs and the key; Mobile sends that key
as a WHIP bearer credential. Web sends only the SDP content type. The reference
MediaMTX configuration has no authorization binding. These are source findings;
provider takeover, actual infrastructure health and production exploitation are
not established. Configured endpoint strings alone cannot repair this boundary.

All legacy event DTOs now return null for playback, ingest, WHIP and key fields,
including owner responses. Broadcasters and followers retain existing metadata
and viewer-heartbeat access; only the broadcaster can end a session. A stored
`live` status is legacy bookkeeping, not verified media delivery. This repair does
not establish heartbeat linearizability, accurate audience counts, crash recovery
or remote revocation. Already disclosed provider credentials require independent
provider reconciliation and rotation; a database `ended` value cannot do that.

RadioStream lacks owner/provenance metadata. Read projections therefore quarantine
URLs with a UUID path segment, the format generated by the old implementation,
across hosts and optional HLS suffixes. Paths are percent-decoded once; a remaining
percent sign is conservatively quarantined too, preventing nested-encoding bypass. Presence reads also withhold such URLs;
direct active-stream/presence writes reject them with503. Import can still
persist matching rows (which reads withhold), and metadata refresh still visits
stored URLs; these paths require separate provider-read reconciliation. This is conservative containment,
not a classifier proving that every matching URL is private: legitimate external
UUID-addressed stations are also withheld. Stored rows are retained. Manually copied or otherwise transformed old keys, cached clients, provider logs
and other application surfaces require separate reconciliation. No assertion of
complete historical credential removal is made.

Mobile remote start, end and heartbeat failures propagate to the caller. A503,
404, network error or authorization rejection must not create/update a local
record and claim remote acceptance. Explicit local mode and existing local IDs
retain their local lifecycle; read fallback is unchanged. The screen test asserts
failed admission neither starts WHIP nor announces success. Best-effort cleanup
after a previously accepted operation remains best effort, not durable recovery.

Re-enablement requires a reviewed provider adapter that separates a nonsecret
playback identifier from publish-only credentials, enforces owner/path/action
binding at the media server, supports revocation/expiry and cleanup, and verifies
ICE/DTLS/media state independently from HTTP resource creation. The reference
stack is not that adapter. RFC9725 sections3,4.7,5 support this distinction; see
RES-STREAM-001. No unchecked environment flag bypass is provided.

Executable checks: actual HTTP/PostgreSQL no-write controls with absent, partial
and complete endpoint configuration; anonymous/nonfollower denial; legacy DTO
redaction, owner cleanup and radio quarantine with an ordinary external station
control; Mobile repository and actual screen regressions. Unit tests cover URL
quarantine boundaries. These are implementation conformance tests, not a formal
refinement proof. No stream is published, provider called or production row
modified by the fixtures. Final exact-revision execution is required.
