## Mathematical contract and abstraction

Let `p` be the signed 64-bit `fromSqlKey auPartyId`. For each RoleEnum constructor
`r`, let `n[r]` be its multiplicity in the role list; let `g(m)` denote membership
of module `m` in `auModules`. Inputs are total, defined values. Roles are a finite
list with `0 <= sum(n) <= 2^63-1`, and every count is nonnegative. This is the
full declared machine-Int length domain, not small-state exploration. Infinite
lists, undefined values, allocation failure and arithmetic beyond that bound are
outside the claim. Order does not affect the recognized operations.

Define:

```
coherent = p > 0 AND forall r: n[r] <= 1
strict = coherent AND n[Admin] = 1
         AND forall r outside {Admin,Fan,Customer}: n[r] = 0
module(m) = coherent AND g(m)
ingestion = strict AND g(ModuleAdmin)
```

The obligations are equivalences between each translated implementation predicate
and its formula, for every input in the domain. Equivalence includes admission
and denial; each additionally has a satisfiable admission witness and a
satisfiable denial witness. The source uniqueness calculation is `sum(n) = sum(if n[r] > 0 then 1 else 0)`.
Three additional UNSAT lemmas justify its reduction to `forall r: n[r] <= 1`:
for any nonnegative count, excess `n - if n > 0 then 1 else 0` is nonnegative;
that excess is zero iff `n <= 1`; and a sum of 31 nonnegative excesses is zero
iff every excess is zero. Algebraic composition/substitution in the translator
remains trusted, while each lemma is machine-checked before results are admitted.
An initial direct cardinality encoding was stopped for excessive solver search;
this decomposition preserves the domain and specification.
Module membership is arbitrary: no legacy role-to-module table is substituted for
persisted grants. Session authenticity or present database authority is not assumed
as a consequence of `p > 0` or of the word “coherent”.

The translation consumes complete recognized definitions and lowers actual Boolean
operators and the actual role allowlist. Unsupported expressions fail closed.
Entire Auth.hs, Models.hs and RecordsIngestion.hs hashes, plus the Stack
manifest/lock and Cabal manifest hashes, pin the reviewed import,
binding and datatype context, so a change outside the recognized functions also
requires translation review. Update those pins only after inspecting semantic
dependencies; a hash by itself is not a proof of semantic correspondence.

## Reproduction and evidence

Use `formal/system/requirements-verification.txt` (z3-solver 4.13.3.0):

```sh
python scripts/verify-auth-predicates.py --output /absolute/new-auth-proof-directory
python scripts/test-auth-predicates.py
```

Exit 0 means three contract formulas and three algebra lemmas were UNSAT, six admission/denial witnesses and five
mutation controls were SAT, and all seventeen serialized inputs replayed. It is not
release approval. Exit 1 means a failed/refuted/inconclusive execution; inspect
`result.json`. An existing output directory is refused without modification.
Unknown, timeout, unsupported source and drift never become PROVEN. Artifacts
include exact SMT-LIB, input hashes, source hashes, commit/dirty status, tool
identity, time, results and SAT valuations. Replay any input with pinned
`z3 -smt2 FILE.smt2`; UNSAT is expected for the three base contracts and three cardinality lemmas; SAT for
the remaining eleven inputs. SMT inputs are not independently checked proof
certificates. Same-solver replay is reproducibility, not independent validation.

Mutations change the source in memory: weaken coherent-role checking, admit
Webmaster into the strict role scope, permit party zero, bypass the module grant,
and allow the Admin module to substitute for strict administration. All must
produce concrete valuations violating an equivalence. These are synthetic guard
regressions, not defects alleged to exist in the current implementation. No
confirmed application defect was found or repaired by these three obligations.
The tests also ensure duplicate roles, unsupported syntax, changed snapshots,
unknown answers and source drift cannot silently gain PROVEN status.

## Trusted base, limitations and release

Trusted: the restricted translator and its manual source-context review, Python,
Z3 4.13.3, SHA-256/Git, OS/hardware, Haskell Prelude list and Boolean semantics,
Data.Set equality/size/membership, Persistent's Int64 key representation and a
64-bit Int target. GHC compilation, packages, runtime evaluation and the
abstraction/translation relation have no machine-checked refinement proof here.
Partial correctness is conditional on defined finite inputs and evaluation
without runtime/resource failure; no executable total-correctness theorem is
claimed. Dependency manifests are pinned too; external/tool/runtime changes still require
reviewing these assumptions.

Method: quantifier-free linear integer arithmetic checks the negation of each
universally intended formula. The SMT integer domain is mathematical, so the
machine bounds are explicit ([Z3 arithmetic semantics](https://microsoft.github.io/z3guide/docs/theories/Arithmetic/)).
Boolean/list interpretation follows the [Haskell 2010 report](https://www.haskell.org/onlinereport/haskell2010/haskellch6.html).
No new axioms, admitted theorems or unsupported-language paths are treated as proof.

Session validation, canonical grant loading, concurrent revocation, stale request
snapshots, dispatch, database effects, UI/native clients, third parties and actual
release-artifact correspondence remain UNPROVEN. Continuous checks rerun every
obligation on PRs, main and the weekly formal workflow; failed proof jobs block
normal quality progression. Full requirement statuses and release blockers are
unchanged: **BLOCKED**, with no accepted unproven critical risk.
