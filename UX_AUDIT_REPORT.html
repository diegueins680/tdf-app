1. Executive Summary

This audit examined the TDF Records platform across web and mobile, covering theme/design system, components, navigation, forms, accessibility, error handling, and cross-platform consistency. The codebase shows strong foundations — well-structured MUI theme, thoughtful feature registry, good i18n infrastructure on web, and solid API client patterns. However, several systemic gaps create a fragmented user experience.

Top 10 Priority Fixes

Add error boundaries to mobile app

Zero error boundaries exist. Any render crash white-screens the entire app with no recovery. Add a root boundary in _layout.tsx and per-screen boundaries for complex screens.

Add offline detection to both platforms

No connectivity detection exists anywhere. Users on flaky mobile networks (common at live events) get generic errors with no indication of the root cause. Add NetInfo (mobile) and navigator.onLine (web) with persistent banners.

Add request timeouts to API clients

Neither platform configures fetch/Axios timeouts. A hung connection blocks the UI indefinitely with spinners. Add 30s timeouts with clear error messages.

Replace all window.confirm() with styled dialogs

7+ web files use native window.confirm() for destructive actions (deleting assets, approving refunds, changing order status). These cannot be styled, are inaccessible, and break the design language.

Fix mobile theme adoption — 9 of 12 components ignore the theme

Most mobile components use hardcoded hex colors, breaking dark mode entirely. Migrate all components to use useAppTheme().colors.

Add password reset to mobile

Web supports full password reset flow; mobile has no recovery path. Users who forget their password on mobile are locked out.

Add accessibility props to mobile screens

5 mobile screens (social, bookings, event live broadcast, event moments, events) have interactive elements with zero accessibility annotations. VoiceOver/TalkBack users cannot use these screens.

Implement i18n on mobile

Web supports 5 languages (en, es, fr, de, pt) with proper translation files. Mobile is hardcoded Spanish with ad-hoc English checks. Same user gets different language on each platform.

Add currency conversion to mobile

Web auto-converts currencies via Frankfurter API. Mobile shows raw USD amounts. Same ticket shows different prices on each platform.

Add analytics events to mobile

All growth/lifecycle events (signup, login, follow, profile saves) are missing on mobile. Product analytics and funnel analysis only capture web users.

2. Critical Issues (Must Fix)

Critical Mobile Error Handling

No error boundaries anywhere in the mobile app

An unhandled render error in any screen crashes the entire app to a white screen (or red box in dev). There is no recovery path — the user must force-quit and restart. Complex screens like eventDetail.tsx (1920 lines) and ticketCheckout.tsx (1165 lines) are particularly vulnerable.

Fix: Add a root-level ErrorBoundary wrapping the navigator in _layout.tsx. Add per-screen boundaries for complex screens. Provide a "Reload" button that calls router.replace('/').
app/_layout.tsx, src/providers/AppProviders.tsx
Critical Both Error Handling

No request timeouts on either platform

The web api() function uses native fetch with no AbortController. The mobile Axios instance has no timeout config. A hung connection will show loading indicators indefinitely with no user recourse.

Fix: Web — add AbortController with 30s default timeout. Mobile — add timeout: 30000 to Axios instance config. Surface timeout-specific error messages.
tdf-hq-ui/src/api/client.ts, tdf-mobile/src/api/client.ts
Critical Both Usability

No offline / connectivity detection

Neither platform detects offline state. There is no @react-native-community/netinfo usage on mobile, no navigator.onLine check on web, no connectivity banner, and no offline queue. Users on flaky connections get generic "No se pudieron cargar..." errors with no indication of the root cause.

Fix: Add NetInfo listener on mobile, navigator.onLine on web. Show persistent "No connection" banner. Queue mutations for retry when connectivity resumes.
All screens (no NetInfo usage found)
Critical Web Usability / Accessibility

window.confirm() used for destructive financial actions

7+ files use window.confirm() for: deleting assets (LabelAssetsPage), approving refunds (RefundManagementPanel), changing order status (MarketplaceOrdersPage), deactivating services (ServiceTypesPage), deleting tasks (InternTaskDetailPage), deleting tracking entries and receipts (CourseRegistrationsAdminPage). Native confirms cannot be styled, are inaccessible, and cannot be localized.

Fix: Create a reusable ConfirmDialog component wrapping MUI Dialog with severity-appropriate styling (red for destructive), keyboard trap, and proper ARIA attributes. Replace all window.confirm() calls.
LabelAssetsPage.tsx:552, RefundManagementPanel.tsx:92, MarketplaceOrdersPage.tsx:683, ServiceTypesPage.tsx:180, InternTaskDetailPage.tsx:234, CourseRegistrationsAdminPage.tsx:6882/6963
Critical Mobile Usability

No unsaved-changes guard on any form screen

None of the multi-field creation/editing forms use useNavigation().preventRemove or beforeRemove. A back gesture or accidental tab switch silently discards all form input. This is particularly painful on createEvent.tsx (10+ fields) and createVenue.tsx (12 fields).

Fix: Implement a shared useUnsavedChanges hook that presents an Alert.alert confirmation dialog before allowing navigation away when form state is dirty.
app/createEvent.tsx, app/createVenue.tsx, app/createArtistProfile.tsx, app/editArtistProfile.tsx
Critical Mobile Theme / Dark Mode

9 of 12 mobile components ignore the theme system

Only FormField, FeatureAccessNotice, and CalendarScreen properly use useAppTheme(). All other components (EventCard, ArtistCard, EventMomentCard, EventLiveBroadcastCard, StagePill, PublicLinksSection, TicketOrderCard, TicketPurchaseCard, SchemaForm) use hardcoded hex colors. Dark mode is completely broken on most screens.

Fix: Migrate all components to use useAppTheme().colors for backgrounds, text, borders, and interactive elements.
src/components/EventCard.tsx, ArtistCard.tsx, EventMomentCard.tsx, EventLiveBroadcastCard.tsx, StagePill.tsx, PublicLinksSection.tsx, tickets/TicketOrderCard.tsx, tickets/TicketPurchaseCard.tsx
Critical Mobile Accessibility

5 mobile screens have zero accessibility annotations on interactive elements

social.tsx (tabs, follow/unfollow buttons), bookings.tsx (list items, create button), EventLiveBroadcastCard (watch/end buttons), EventMomentCard (reactions, comments, media), and events.tsx (search, toggles) have interactive elements with no accessibilityRole, accessibilityLabel, or accessibilityState. VoiceOver/TalkBack users cannot meaningfully interact with these screens.

Fix: Add accessibilityRole="button", descriptive accessibilityLabel, and accessibilityState to all interactive elements. Mirror the pattern from auth.tsx and inventory.tsx which do this correctly.
app/(tabs)/social.tsx, app/(tabs)/bookings.tsx, src/components/EventLiveBroadcastCard.tsx, EventMomentCard.tsx, app/(tabs)/events.tsx
Critical Mobile Authentication

No password reset on mobile

Web supports full password reset flow (requestPasswordReset, confirmPasswordReset). Mobile has no recovery path. Users who forget their password on mobile are permanently locked out.

Fix: Implement password reset flow in mobile auth screen, matching the web's API calls.
app/auth.tsx (missing), tdf-hq-ui/src/api/auth.ts (reference)
Critical Mobile Internationalization

No i18n framework on mobile — hardcoded Spanish

Web supports 5 languages (en, es, fr, de, pt) with i18next and proper translation files. Mobile has no i18n framework, no translation files, and all strings are hardcoded in Spanish. Some screens mix English and Spanish unpredictably. A French-speaking user gets a French web experience but a Spanish-only mobile experience.

Fix: Adopt react-i18next or expo-localization + translation files on mobile. At minimum, centralize all strings through a locale-aware helper.
All mobile screens (no i18n imports found)
Critical Mobile Feature Parity

No currency conversion on mobile

Web auto-converts currencies via Frankfurter API with localStorage caching and user preference sync. Mobile shows raw USD amounts. A user whose preferred currency is EUR sees EUR prices on web but USD on mobile for the same event — directly affecting purchasing decisions.

Fix: Port the currency conversion logic from web's CurrencyContext.tsx to mobile. Read exchange rates and cache in AsyncStorage.
tdf-hq-ui/src/contexts/CurrencyContext.tsx (reference), tdf-mobile (missing)
Critical Mobile Analytics

All growth/lifecycle analytics events missing on mobile

Mobile is missing: signup_started, signup_completed, login_completed, fan_profile_saved, artist_profile_saved, artist_followed, feature_navigation_selected, feature_search_no_results, feature_favorite_changed, quick_create_selected. Funnel analysis and conversion tracking only capture web users, making product decisions unreliable.

Fix: Add PostHog capture() calls for all lifecycle events in mobile auth, profile, and navigation flows.
tdf-mobile/src/analytics/posthog.ts, app/auth.tsx, app/(tabs)/*.tsx
Critical Web Accessibility

No skip-navigation link in root HTML

The root index.html has no skip link to jump past the persistent TopBar + SidebarNav to main content. Keyboard users must tab through every top-bar control and every sidebar item on every page load. (Note: AppShell.tsx does have a skip link component, but it targets internal navigation — the root HTML needs one too for initial page load.)

Fix: Add a visually-hidden <a href="#main" class="skip-link">Saltar al contenido</a> as the first child of <body> in index.html.
tdf-hq-ui/index.html
Critical Mobile Usability

Date/time entry requires manual ISO 8601 string input

On createEvent.tsx, start time and end time are entered by typing ISO strings (YYYY-MM-DDTHH:mm:ssZ) into plain TextInput fields. Users must know the ISO format. There are shortcut buttons ("Ahora", "+1h") but no native date/time picker.

Fix: Replace with @react-native-community/datetimepicker. Keep shortcut buttons as quick-fill options.
app/createEvent.tsx lines 299-370

3. Accessibility & Inclusion

Web — Color Contrast Failures

MajorWebWCAG 1.4.3

Primary and secondary colors fail WCAG AA contrast

primary.light: '#8b5cf6' on white is ~3.6:1 (fails AA). secondary.main: '#e11d48' on white is ~4.0:1 (fails AA for normal text). text.secondary: '#6b6b74' on #f8f7f5 is ~4.2:1 (fails AA).

Fix: Darken primary.light to at least #7c3aed. Darken secondary.main to #be123c. Darken text.secondary to ~#595963.

Web — Dialog Accessibility

MajorWebWCAG 2.4.3, 4.1.2

WaitlistJoinDialog and TicketTransferDialog missing focus management

Both dialogs lack aria-labelledby, initial focus management, and focus restoration on close. Submit buttons use onClick instead of type="submit", so pressing Enter doesn't submit. Error alerts have no role="alert" and are not focused.

Fix: Mirror the pattern from StripeCheckoutModal which handles all of these correctly.

Web — Missing ARIA on Public Pages

MajorWebWCAG 1.3.1, 1.1.1

ArtistPublicPage has zero ARIA attributes

The 588-line ArtistPublicPage.tsx has zero aria-* or role= attributes. Hero images, release cards, follow buttons, and external links have no programmatic labeling.

Fix: Audit all images for alt; add aria-label to icon-only buttons; wrap regions in semantic landmarks; verify heading hierarchy.

Mobile — Touch Target Sizes

MajorMobileiOS HIG

Multiple interactive elements below 44pt minimum

EventCard save button (~28pt), EventLiveBroadcastCard watch/end buttons (~35pt), EventMomentCard connect button (~32pt), reaction chips (~32pt), comment button (~34pt) all fall below the iOS 44x44pt minimum touch target.

Fix: Add minHeight: 44 to all TouchableOpacity elements. Use hitSlop as an alternative for small icon buttons.

Mobile — Dynamic Type Support

MajorMobileWCAG 1.4.4

All text uses hardcoded fontSize — no Dynamic Type support

All StyleSheet.create calls use hardcoded pixel sizes. Many layouts use fixed heights and numberOfLines that will break at larger text scales. No maxFontSizeMultiplier is set anywhere.

Fix: Audit at 200% text scale. Set maxFontSizeMultiplier={1.5} on Text/TextInput where layout would break. Replace fixed-height containers with minHeight.

Web — Typography Scale Gap

MajorWebConsistency

No h1 or h2 typography variants defined

The theme defines h3 through caption but no h1 or h2. Components needing large headings use inline sx overrides, leading to inconsistency. The caption variant at 11px is below the 12px minimum for legibility.

Fix: Define h1 and h2 in the typography config. Increase caption to 0.75rem (12px).

Mobile — Font Sizes Below Minimum

MajorMobileAccessibility

9pt and 11pt text used in multiple components

EventCard uses fontSize: 9 for "DESDE" eyebrow text. ArtistCard, TicketOrderCard, and others use fontSize: 11. These are below the commonly recommended 12pt minimum for legibility.

Fix: Establish 12pt as minimum body text size. Use uppercase + letterSpacing for visual distinction instead of tiny fonts.

4. Theme, Design System & Dark Mode

Hardcoded Colors Bypassing Theme

MajorWebConsistency

6+ web components use raw hex/rgba values instead of theme tokens

PublicBrandBar.tsx uses hardcoded rgba values that will look broken in light mode. ApiStatusChip.tsx, InstagramEntryLinks.tsx, RadioWidget.tsx, AdminUserCommunicationDialog.tsx, and BasicFeaturePage.tsx all use raw Tailwind-style color values not from the theme.

Fix: Create a lint rule or script to flag raw hex/rgba values in sx props. Route everything through theme tokens.
MajorMobileDark Mode

Most mobile screens use hardcoded colors — dark mode broken

Screens using hardcoded hex: events.tsx, social.tsx, bookings.tsx, parties.tsx, pipelines.tsx, createEvent.tsx, createVenue.tsx, artistDetail.tsx, venueDetail.tsx, venueExplorer.tsx, userProfile.tsx. Only auth.tsx, operations.tsx, inventory.tsx, more.tsx, create.tsx, ddex/index.tsx, and CalendarScreen.tsx properly use the theme.

Fix: Migrate all screens to use useAppTheme().colors.

Divider Visibility

MinorWebVisual

Dividers use very low opacity — nearly invisible

divider: rgba(0,0,0,0.06) / rgba(255,255,255,0.06) are nearly invisible, especially on lower-quality displays.

Fix: Increase to at least 0.09 or 0.10.

Button/Card Hover Effects

MinorWebUsability

Hover transforms applied to ALL buttons and cards, including non-interactive ones

MuiButton hover applies translateY(-1px) + box-shadow to ALL buttons including text buttons. MuiCard hover applies translateY(-2px) to ALL cards including static content cards, causing jitter.

Fix: Scope hover effects to contained/outlined variants and explicitly interactive cards.

5. Navigation & Information Architecture

Web — No Per-Page Document Titles

MajorWebUsability

Every page shows "TDF Records" in the browser tab

The HTML document title is statically set and there is zero usage of document.title, react-helmet, or any equivalent. Users with many tabs open cannot distinguish which TDF page is which.

Fix: Create a useDocumentTitle(title) hook and call it from every page or from the route configuration.

Web — DataTable Underutilized

MajorWebUsability

Well-designed DataTable component is not used by most pages

DataTable provides sorting slots, pagination, empty states, skeleton loading, and sticky headers — but most pages (PartiesPage, LeadsPage, PaymentsPage, InventoryPage, LabelArtistsPage, AdminUsersPage) build their own raw MUI tables. No data tables support client-side column sorting.

Fix: Migrate pages to use DataTable. Add sortable column headers with TableSortLabel.

Mobile — No Pull-to-Refresh on Primary Screens

MajorMobileUsability

Pull-to-refresh missing from events, social, profile, bookings, parties

Only inventory.tsx, operations.tsx, and ddex/index.tsx implement pull-to-refresh. Users on the most-visited screens have no way to manually refresh stale data.

Fix: Add <RefreshControl> to every FlatList and ScrollView-based screen.

Mobile — No Pagination on List Screens

MajorMobilePerformance

Events, parties, bookings, artist/venue events load ALL records at once

The events screen loads all upcoming events with no pagination or onEndReached. As the catalog grows, this causes increasingly long load times and high memory usage. Only operations.tsx uses useInfiniteQuery.

Fix: Convert to useInfiniteQuery with cursor-based pagination and wire onEndReached.

Web — Sidebar "/" Shortcut Conflicts

MajorWebUsability

Sidebar "/" shortcut steals focus from contentEditable elements

The sidebar listens for "/" to focus search. The guard checks activeTag === 'input' but does NOT check isContentEditable. If a user is editing a rich-text element and presses "/", the sidebar search steals focus.

Fix: Add || (event.target as HTMLElement)?.isContentEditable to the guard.
SidebarNav.tsx lines 857-868

Mobile — Massive Feature Gap vs Web

MajorMobileFeature Parity

Entire web sections have no mobile equivalent

Missing on mobile: Finance (payments, reports), School (teachers, classes), Label management (artists, projects, releases), Configuration/Admin (users, roles, CMS), CRM (contacts, companies), Chat, Docs, Internships, Fan Club management, Instagram OAuth, WhatsApp consent.

Fix: If intentional (mobile = consumer, web = admin), document clearly. If parity is a goal, prioritize most-used admin flows.

6. Forms & Data Entry

Web — react-hook-form + zod Installed but Never Used

MajorWebValidation

Form libraries declared as dependencies but zero source files import them

react-hook-form, @hookform/resolvers, and zod are in package.json but never imported. All validation is hand-rolled with imperative if checks. This produces inconsistent validation, no typed form state, and no reusable rules.

Fix: Adopt react-hook-form + zod for all forms. Define shared Zod schemas for recurring field types.

Web — Validation Errors Not Inline

MajorWebUsability

Validation errors shown as top-level Alert, never inline per field

Most forms display a single <Alert severity="error"> at the top/bottom. Users must read a generic message and visually scan all fields. No per-field error highlighting with error and helperText props.

Fix: Use per-field error and helperText props on MUI TextField.

Mobile — Missing KeyboardAvoidingView

MajorMobileUsability

createVenue, createEvent, userProfile, artist forms lack KeyboardAvoidingView

When the keyboard opens on iOS, bottom fields and submit buttons are hidden behind the keyboard. Only auth.tsx and ticketCheckout.tsx properly wrap forms in KeyboardAvoidingView.

Fix: Wrap ScrollView in <KeyboardAvoidingView behavior={Platform.OS === 'ios' ? 'padding' : undefined}>.

Mobile — No Focus Management in Forms

MajorMobileUsability

createVenue (12 fields), createArtistProfile, editArtistProfile have no field focus chaining

No returnKeyType="next", no onSubmitEditing to advance focus, no useRef for focus management. Users must manually tap each field. Only auth.tsx implements this correctly.

Fix: Add returnKeyType="next" and chain onSubmitEditing to focus the next field.

Mobile — Alert.alert() for All Validation

MajorMobileUsability

All validation errors shown as blocking Alert.alert() popups

Each validation error pops a system dialog that must be dismissed before fixing the field. For a 12-field form, the user may need to dismiss 3-4 sequential alerts. The FormField component already supports inline errors.

Fix: Display inline errors below each field. Migrate forms to use FormField instead of raw TextInput.

Both — No Auto-Save / Draft Functionality

MajorBothUsability

Complex forms have no draft/auto-save — data lost on navigation

Web: Invoice generation, course builder, radio management, fan profile editor have no drafts. Mobile: All creation forms lose data if app is backgrounded. Only InscripcionPage.tsx (web) uses localStorage persistence.

Fix: Implement localStorage (web) / AsyncStorage (mobile) draft saving with debounce for forms with 5+ fields.

Mobile — FormField Component Unused by Major Forms

MajorMobileAccessibility

Well-designed FormField component exists but major creation forms use raw TextInput

FormField.tsx has label, optional marker, hint text, error display, focus styling, accessibility attributes, and theme support. But createVenue, createEvent, createArtistProfile, editArtistProfile use raw TextInput with separate Text labels.

Fix: Migrate all creation/edit forms to use FormField. This is the single highest-impact change for mobile form quality.

7. Error Handling, Loading & Feedback

Web — No Global Toast System

MajorWebFeedback

Each page implements its own ad-hoc toast pattern

No global toast/notification system exists. Each page uses local useState + MUI Snackbar/Alert. TeacherPortalPage alone has 4 separate toast state variables. Inconsistent positioning, timing, and styling.

Fix: Adopt notistack or a shared context-based toast hook.

Web — No Optimistic UI Updates

MajorWebFeedback

Only SocialInboxPage uses optimistic updates

No other mutation across the entire web app uses optimistic UI. Users wait for server round-trips for all actions (RSVP, save, status changes) with no immediate visual feedback.

Fix: Implement optimistic updates for high-frequency mutations using React Query's onMutate/onError rollback pattern.

Web — Full-Viewport Loading Flash

MajorWebFeedback

RouteLoadingFallback shows full-viewport spinner for all lazy routes

For fast navigations this creates a jarring full-screen flash. Should use skeleton or inline loading for known page layouts.

Fix: Reserve full-screen fallback for initial app load. Use skeleton placeholders for route transitions.

Mobile — No Skeleton Loading Anywhere

MajorMobileFeedback

Every loading state uses centered ActivityIndicator

No skeleton loading components exist anywhere in the mobile app. This creates a "blank screen" feeling during navigation, especially on slower connections.

Fix: Implement skeleton screens for key views (events list, ticket orders, event detail).

Mobile — Blocking Alert.alert() for All Feedback

MajorMobileFeedback

Every success, error, and info message forces user to tap "OK"

After RSVP, saving an event, sending invitations, publishing moments — all require dismissing an alert before continuing. This interrupts flow for non-critical feedback.

Fix: Use non-blocking toast system for success/info. Reserve Alert.alert for errors requiring user decision.

Web — No Undo Functionality

MajorWebUsability

No undo anywhere — destructive actions are immediate and irreversible

Delete, refund approval, status changes are all immediate with no undo. Users have no safety net for accidental actions.

Fix: Implement "toast with undo" pattern for non-critical destructive actions. Keep confirmation dialogs for truly irreversible operations.

Web — Error Boundary Only Offers Full Reload

MajorWebUsability

AppErrorBoundary destroys all state on recovery

The only recovery action is window.location.reload(). This destroys unsaved form data, navigation history, and sidebar preferences. No "Go to home" or "Go back" option.

Fix: Add "Ir al inicio" button and consider a "Go back" button. Add per-route-section error boundaries.

8. Cross-Platform Consistency

Different Font Families

MajorBothConsistency

Web uses Inter; mobile uses system fonts

Users switching between platforms notice different typefaces. The mobile designTokens.ts acknowledges: "Until Inter is bundled, use each platform's deterministic system face."

Fix: Bundle Inter font in mobile via expo-font.

Different HTTP Clients

MajorBothArchitecture

Web uses fetch; mobile uses axios — different error shapes and patterns

Different HTTP libraries mean different interceptor patterns, different error shapes, and different testing approaches. Web has request activity tracking; mobile lacks it.

Fix: Consider standardizing on one library, or at minimum ensure error shapes are normalized consistently.

React Query Adoption Gap

MajorBothArchitecture

Web uses React Query extensively; mobile barely uses it

Web has ~397 matches for useQuery/useMutation. Mobile has ~8 matches. Web gets automatic background refetching, cache sharing, and optimistic updates. Mobile may show more loading spinners and stale data.

Fix: Increase React Query adoption on mobile for consistent caching behavior.

No Centralized Date Formatting on Mobile

MajorMobileConsistency

Web has centralized formatters; mobile formats dates ad-hoc per component

Web has formatters.ts with formatCurrency, formatDate, formatDateTime respecting user preferences. Mobile formats dates inline per component, potentially showing the same event date differently.

Fix: Create a shared formatters.ts in mobile mirroring the web's API.

Signup Field Parity

MajorMobileFeature Parity

Mobile signup hardcodes roles: ['Fan'] and omits many web fields

Web signup has: firstName, lastName, email, phone, roles, internship fields, fanArtistIds, claimArtistId. Mobile signup has only: firstName, lastName, email, password, roles: ['Fan']. Mobile users cannot claim artist profiles during registration.

Fix: Add missing fields to mobile signup flow.

Mixed Language in Validation Messages

MinorBothi18n

Validation messages mix English and Spanish unpredictably

createEvent.tsx: "Validation" (EN) title with "El nombre del evento es obligatorio" (ES) message. TicketTransferDialog.tsx: "Please fill in all fields" (EN) while UI is Spanish. venueDetail.tsx: Section headers in EN, error messages in ES.

Fix: Centralize all validation messages through i18n.

9. Performance & Architecture

Oversized Components

MinorBothMaintainability

Several components exceed 1000+ lines

Web: BookingsPage (2072 lines), FanHubPage (1333+), AdminUsersPage (1326+), InventoryPage (1326+), LoginPage (1659). Mobile: eventDetail.tsx (1920 lines), ticketCheckout.tsx (1165 lines). These are hard to maintain, test, and optimize.

Fix: Extract sub-components. For BookingsPage, extract BookingFormDialog, BookingCalendar, DuplicateBookingModal. For eventDetail, extract EventDetailsTab, EventMomentsTab, EventLiveTab.

N+1 Query Pattern

MinorMobilePerformance

Saved events loaded individually via N+1 pattern

Saved events are fetched by calling Events.getById(savedEventId) individually for each saved event via Promise.allSettled. 20 saved events = 20 parallel HTTP requests.

Fix: Add a batch endpoint Events.getByIds(ids: string[]).

Social Screen Uses ScrollView Instead of FlatList

MinorMobilePerformance

Followers/following list renders all items without virtualization

social.tsx uses activeData.map() inside a ScrollView. For users with many connections, this causes performance issues.

Fix: Replace with FlatList for proper virtualization.

10. What's Working Well

The audit also identified many areas of strong implementation worth preserving and extending:

Web accessibility maturity

TopBar, SidebarNav, NotificationBell, StripeCheckoutModal, ReactionBar, ApiErrorNotice, and PageShell all use ARIA attributes correctly. Keyboard navigation is well-handled. Focus is restored after modal close. <html lang="es"> is set.

Mobile FormField component

Exemplary accessibility: accessibilityLabelledBy, accessibilityHint, accessibilityState.disabled, error text with accessibilityRole="alert" + accessibilityLiveRegion="polite", generated nativeID linkage. This pattern should be extended to all forms.

Mobile inventory screen

Thoroughly labeled with 79 accessibility props: radiogroup/radio, headers, labels, hints, states. This is the gold standard for mobile accessibility in the codebase.

Web i18n infrastructure

Full i18next setup with 5 locales (en, es, fr, de, pt), locale files, useTranslation() hook, locale persistence to localStorage + backend sync. This foundation should be ported to mobile.

Web currency conversion system

Full currency conversion via Frankfurter API with localStorage caching (24h TTL), formatMoney() auto-conversion, and exchange rate auditing. Well-designed and user-centric.

Web error handling components

ApiErrorNotice with retry button, ApiLoadingNotice, EmptyState component with icon/title/description/action, and PageShell with skeleton loading support. These patterns should be used more consistently.

Feature registry architecture

Centralized feature registry with role-based access control, bilingual support, navigation group organization, and evaluation functions. Used consistently by both sidebar and top bar for navigation.

Design token alignment

Base palette values match between web and mobile (primary, secondary, background, text colors). The 4px spacing base unit is consistent. Border radii are nearly identical (2px difference on "md").

Mobile auth screen

Proper accessibility: accessibilityRole="tab" + accessibilityState.selected, error text with accessibilityRole="alert" + accessibilityLiveRegion="assertive", buttons expose busy state. Good focus management and KeyboardAvoidingView.

Web StripeCheckoutModal

Multi-step form with proper focus management, error refocusing, useReducer for state, ARIA attributes, and focus restoration. This is the model for complex form implementations.
