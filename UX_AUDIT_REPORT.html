1. Executive Summary

This audit examined the TDF Records platform across web and mobile, covering theme/design system, components, navigation, forms, accessibility, error handling, and cross-platform consistency. The codebase shows strong foundations — well-structured MUI theme, thoughtful feature registry, good i18n infrastructure on web, and solid API client patterns. However, several systemic gaps create a fragmented user experience.

Top 10 Priority Fixes

Add error boundaries to mobile app

Zero error boundaries exist. Any render crash white-screens the entire app with no recovery. Add a root boundary in _layout.tsx and per-screen boundaries for complex screens.

Add offline detection to both platforms

No connectivity detection exists anywhere. Users on flaky mobile networks (common at live events) get generic errors with no indication of the root cause.

Add request timeouts to API clients

Neither platform configures fetch/Axios timeouts. A hung connection blocks the UI indefinitely with spinners. Add 30s timeouts with clear error messages.

Replace all window.confirm() with styled dialogs

7+ web files use native window.confirm() for destructive actions (deleting assets, approving refunds, changing order status). These are inaccessible and break the design language.

Fix mobile theme adoption — 9 of 12 components ignore the theme

Most mobile components use hardcoded hex colors, breaking dark mode entirely. Migrate all components to useAppTheme().colors.

Add password reset to mobile

Web supports full password reset flow; mobile has no recovery path. Users who forget their password on mobile are locked out.

Add accessibility props to mobile screens

5 mobile screens have interactive elements with zero accessibility annotations. VoiceOver/TalkBack users cannot use these screens.

Implement i18n on mobile

Web supports 5 languages with proper translation files. Mobile is hardcoded Spanish. Same user gets different language on each platform.

Add currency conversion to mobile

Web auto-converts currencies via Frankfurter API. Mobile shows raw USD amounts. Same ticket shows different prices on each platform.

Add analytics events to mobile

All growth/lifecycle events (signup, login, follow, profile saves) are missing on mobile. Product analytics only capture web users.

2. Critical Issues (Must Fix)

CriticalMobileError Handling

No error boundaries anywhere in the mobile app

An unhandled render error crashes the entire app to a white screen with no recovery path. Complex screens like eventDetail.tsx (1920 lines) and ticketCheckout.tsx (1165 lines) are particularly vulnerable.

→ Add root-level ErrorBoundary in _layout.tsx + per-screen boundaries for complex screens.
app/_layout.tsx, src/providers/AppProviders.tsx
CriticalBothError Handling

No request timeouts on either platform

Web fetch has no AbortController. Mobile Axios has no timeout. A hung connection shows spinners indefinitely.

→ Web: add AbortController with 30s timeout. Mobile: add timeout: 30000 to Axios config.
tdf-hq-ui/src/api/client.ts, tdf-mobile/src/api/client.ts
CriticalBothUsability

No offline / connectivity detection

No NetInfo on mobile, no navigator.onLine on web, no connectivity banner, no offline queue. Users on flaky connections get generic errors.

→ Add NetInfo (mobile) + navigator.onLine (web) with persistent "No connection" banner.
CriticalWebUsability / A11y

window.confirm() for destructive financial actions

7+ files use native confirms for: deleting assets, approving refunds, changing order status, deactivating services, deleting tasks/receipts. Cannot be styled, inaccessible, unlocalizable.

→ Create reusable MUI ConfirmDialog with severity styling, keyboard trap, ARIA. Replace all calls.
LabelAssetsPage:552, RefundManagementPanel:92, MarketplaceOrdersPage:683, ServiceTypesPage:180, +3 more
CriticalMobileUsability

No unsaved-changes guard on any form screen

Back gesture or tab switch silently discards all form input on createEvent (10+ fields), createVenue (12 fields), artist profile forms.

→ Implement shared useUnsavedChanges hook with usePreventRemove + confirmation dialog.
CriticalMobileDark Mode

9 of 12 mobile components ignore the theme system

Only FormField, FeatureAccessNotice, and CalendarScreen use useAppTheme(). All others use hardcoded hex colors. Dark mode is completely broken.

→ Migrate all components to useAppTheme().colors.
EventCard, ArtistCard, EventMomentCard, EventLiveBroadcastCard, StagePill, PublicLinksSection, TicketOrderCard, TicketPurchaseCard
CriticalMobileAccessibility

5 mobile screens have zero accessibility annotations

social.tsx, bookings.tsx, EventLiveBroadcastCard, EventMomentCard, events.tsx — interactive elements with no accessibilityRole, accessibilityLabel, or accessibilityState.

→ Add a11y props to all interactive elements. Mirror auth.tsx and inventory.tsx patterns.
CriticalMobileAuth

No password reset on mobile

Web supports full password reset. Mobile has no recovery path — users who forget their password are locked out.

→ Implement password reset flow matching web's API calls.
CriticalMobilei18n

No i18n framework — hardcoded Spanish

Web supports 5 languages (en, es, fr, de, pt). Mobile has no i18n, all strings hardcoded Spanish. Some screens mix EN/ES unpredictably.

→ Adopt react-i18next or expo-localization + translation files.
CriticalMobileFeature Parity

No currency conversion on mobile

Web auto-converts currencies. Mobile shows raw USD. Same ticket shows different prices on each platform.

→ Port CurrencyContext logic from web to mobile with AsyncStorage caching.
CriticalMobileAnalytics

All growth/lifecycle analytics events missing

Missing: signup_started/completed, login_completed, fan/artist_profile_saved, artist_followed, feature_navigation_selected, etc. Funnel analysis only captures web users.

→ Add PostHog capture() calls for all lifecycle events in mobile.
CriticalMobileUsability

Date/time entry requires manual ISO 8601 string input

createEvent.tsx requires typing "YYYY-MM-DDTHH:mm:ssZ" into TextInput. Users must know ISO format.

→ Replace with @react-native-community/datetimepicker. Keep shortcut buttons.

3. Accessibility & Inclusion

MajorWebWCAG 1.4.3

Primary/secondary colors fail WCAG AA contrast

primary.light (#8b5cf6) on white = ~3.6:1 (fails). secondary.main (#e11d48) = ~4.0:1 (fails). text.secondary (#6b6b74) on #f8f7f5 = ~4.2:1 (fails).

→ Darken primary.light to #7c3aed, secondary.main to #be123c, text.secondary to ~#595963.
MajorWebWCAG 2.4.3

Dialogs missing focus management (WaitlistJoin, TicketTransfer)

No aria-labelledby, no initial focus, no focus restore on close. Submit buttons use onClick instead of type="submit". Error alerts not announced.

→ Mirror StripeCheckoutModal pattern which handles all of these correctly.
MajorWebWCAG 1.3.1

ArtistPublicPage (588 lines) has zero ARIA attributes

Hero images, release cards, follow buttons, external links — no programmatic labeling whatsoever.

→ Audit all images for alt; add aria-label to icon buttons; use semantic landmarks.
MajorMobileiOS HIG

Touch targets below 44pt minimum

EventCard save (~28pt), broadcast watch/end (~35pt), moment connect (~32pt), reaction chips (~32pt), comment button (~34pt).

→ Add minHeight: 44 to all TouchableOpacity elements.
MajorMobileWCAG 1.4.4

No Dynamic Type support — hardcoded font sizes everywhere

All StyleSheet.create uses hardcoded px. No maxFontSizeMultiplier set. Layouts break at larger text scales.

→ Set maxFontSizeMultiplier={1.5} on Text/TextInput. Replace fixed heights with minHeight.
MajorMobileA11y

9pt and 11pt text used in multiple components

EventCard fontSize:9, ArtistCard/TicketOrderCard fontSize:11 — below 12pt minimum for legibility.

→ Establish 12pt minimum. Use uppercase + letterSpacing for visual distinction.
MajorWebTypography

No h1/h2 typography variants defined

Theme defines h3-caption but no h1/h2. Components use inline sx overrides. Caption at 11px is below 12px minimum.

→ Define h1/h2 in typography config. Increase caption to 0.75rem (12px).

4. Theme, Design System & Dark Mode

MajorWebConsistency

6+ web components use raw hex/rgba instead of theme tokens

PublicBrandBar, ApiStatusChip, InstagramEntryLinks, RadioWidget, AdminUserCommunicationDialog, BasicFeaturePage all use raw Tailwind-style values.

→ Create lint rule to flag raw hex/rgba in sx props. Route everything through theme tokens.
MajorMobileDark Mode

11+ mobile screens use hardcoded colors — dark mode broken

events, social, bookings, parties, pipelines, createEvent, createVenue, artistDetail, venueDetail, venueExplorer, userProfile all use hardcoded hex.

→ Migrate all screens to useAppTheme().colors.
MinorWebVisual

Dividers nearly invisible at 0.06 opacity

rgba(0,0,0,0.06) / rgba(255,255,255,0.06) barely visible on lower-quality displays.

→ Increase to at least 0.09 or 0.10.
MinorWebUsability

Hover transforms on ALL buttons/cards including non-interactive ones

translateY(-1px) on text buttons, translateY(-2px) on static content cards causes jitter.

→ Scope hover to contained/outlined variants and explicitly interactive cards.

5. Navigation & Information Architecture

MajorWebUsability

Every page shows "TDF Records" in browser tab — no per-page titles

Zero usage of document.title or react-helmet. Users with many tabs cannot distinguish pages.

→ Create useDocumentTitle() hook. Call from every page or route config.
MajorWebUsability

DataTable component underutilized — no column sorting anywhere

Most pages build raw MUI tables. No client-side column sorting on any table. Inconsistent pagination, empty states, and styling.

→ Migrate pages to DataTable. Add sortable column headers with TableSortLabel.
MajorMobileUsability

No pull-to-refresh on events, social, profile, bookings, parties

Only inventory, operations, ddex implement it. Most-visited screens have no manual refresh.

→ Add RefreshControl to every FlatList and ScrollView-based screen.
MajorMobilePerformance

No pagination on events, parties, bookings — loads ALL records

Only operations.tsx uses useInfiniteQuery. Growing catalogs cause long load times and high memory.

→ Convert to useInfiniteQuery with cursor-based pagination + onEndReached.
MajorWebUsability

Sidebar "/" shortcut steals focus from contentEditable elements

Guard checks input/textarea but not isContentEditable. Rich-text editors lose focus when "/" is pressed.

→ Add isContentEditable check to the guard, matching TopBar's implementation.
MajorMobileFeature Parity

Entire web sections missing from mobile

Finance, School, Label management, Configuration/Admin, CRM, Chat, Docs, Internships, Fan Club management — none available on mobile.

→ If intentional (mobile=consumer, web=admin), document clearly. Otherwise prioritize admin flows.

6. Forms & Data Entry

MajorWebValidation

react-hook-form + zod installed but never imported

Both libraries are in package.json but zero source files use them. All validation is hand-rolled imperative if-checks.

→ Adopt react-hook-form + zod for all forms. Define shared Zod schemas.
MajorWebUsability

Validation errors as top-level Alert, never inline per field

Users see generic "Completa todos los campos" and must scan all fields to find which are invalid.

→ Use per-field error + helperText props on MUI TextField.
MajorMobileUsability

Missing KeyboardAvoidingView on 4+ form screens

createVenue, createEvent, userProfile, artist forms — bottom fields hidden behind keyboard on iOS.

→ Wrap in KeyboardAvoidingView behavior="padding" (iOS).
MajorMobileUsability

No focus management / field chaining in forms

createVenue (12 fields), artist forms — no returnKeyType="next", no onSubmitEditing. Users tap each field manually.

→ Add returnKeyType="next" + chain onSubmitEditing to focus next field via refs.
MajorMobileUsability

Alert.alert() for all validation — blocking, one-at-a-time

Each error pops a system dialog. 12-field form may need 3-4 sequential alert dismissals.

→ Use inline errors via FormField component. Reserve Alert.alert for critical decisions.
MajorBothUsability

No auto-save / drafts on complex forms

Web: invoice, course builder, radio, fan profile. Mobile: all creation forms. Data lost on navigation/background.

→ localStorage (web) / AsyncStorage (mobile) draft saving with debounce for 5+ field forms.
MajorMobileA11y

FormField component unused by major creation forms

FormField has labels, errors, a11y, theming — but createVenue, createEvent, artist forms use raw TextInput.

→ Migrate all creation/edit forms to FormField. Single highest-impact mobile form change.

7. Error Handling, Loading & Feedback

MajorWebFeedback

No global toast system — each page invents its own

TeacherPortalPage has 4 separate toast state variables. Inconsistent positioning, timing, styling.

→ Adopt notistack or shared context-based toast hook.
MajorWebFeedback

No optimistic UI updates (except SocialInboxPage)

Users wait for server round-trips for RSVP, save, status changes with no immediate feedback.

→ Implement onMutate/onError rollback for high-frequency mutations via React Query.
MajorWebFeedback

Full-viewport loading spinner flash on every route transition

RouteLoadingFallback shows full-screen spinner for all lazy routes, creating jarring flash on fast navigations.

→ Use skeleton/inline loading for known layouts. Reserve full-screen for initial load.
MajorMobileFeedback

No skeleton loading anywhere — only centered spinners

Every loading state is a bare ActivityIndicator. Creates "blank screen" feeling on slower connections.

→ Implement skeleton screens for events list, ticket orders, event detail.
MajorMobileFeedback

Blocking Alert.alert() for ALL feedback including success

RSVP, save event, send invitation, publish moment — all require dismissing alert before continuing.

→ Use non-blocking toasts for success/info. Reserve Alert.alert for errors needing decisions.
MajorWebUsability

No undo functionality — destructive actions are immediate

Delete, refund approval, status changes — all immediate with no safety net.

→ Implement "toast with undo" for non-critical actions. Keep confirms for irreversible ops.
MajorWebUsability

Error boundary only offers full page reload — destroys all state

No "Go home" or "Go back" option. Loses unsaved forms, navigation history, preferences.

→ Add "Ir al inicio" button + per-route-section error boundaries.

8. Cross-Platform Consistency

MajorBothConsistency

Different font families — Inter (web) vs system fonts (mobile)

Users switching platforms notice different typefaces. Mobile acknowledges: "Until Inter is bundled..."

→ Bundle Inter font in mobile via expo-font.
MajorBothArchitecture

Different HTTP clients — fetch (web) vs axios (mobile)

Different error shapes, interceptor patterns, testing approaches. Web has request tracking; mobile lacks it.

→ Standardize on one library or normalize error shapes consistently.
MajorBothArchitecture

React Query: extensive on web (~397 uses), minimal on mobile (~8)

Web gets background refetching, cache sharing, optimistic updates. Mobile shows more spinners and stale data.

→ Increase React Query adoption on mobile.
MajorMobileConsistency

No centralized date formatting — ad-hoc per component

Web has formatters.ts with formatCurrency/formatDate/formatDateTime respecting user prefs. Mobile formats inline.

→ Create shared formatters.ts in mobile mirroring web's API.
MajorMobileFeature Parity

Signup hardcodes roles: ['Fan'], omits many web fields

Web: phone, internship fields, fanArtistIds, claimArtistId. Mobile: only name/email/password/Fan role.

→ Add missing fields to mobile signup flow.
MinorBothi18n

Validation messages mix English and Spanish unpredictably

createEvent: "Validation" (EN) + "El nombre es obligatorio" (ES). venueDetail: headers EN, errors ES.

→ Centralize all validation messages through i18n.

9. Performance & Architecture

MinorBothMaintainability

Several components exceed 1000+ lines

Web: BookingsPage (2072), FanHubPage (1333+), AdminUsersPage (1326+), InventoryPage (1326+), LoginPage (1659). Mobile: eventDetail (1920), ticketCheckout (1165).

→ Extract sub-components: BookingFormDialog, BookingCalendar, EventDetailsTab, EventMomentsTab, etc.

Saved events loaded via N+1 pattern (20 events = 20 HTTP requests)

Promise.allSettled with individual getById calls. Need batch endpoint.

→ Add Events.getByIds(ids: string[]) endpoint.
MinorMobilePerformance

Social screen uses ScrollView instead of FlatList

activeData.map() inside ScrollView renders all items without virtualization.

→ Replace with FlatList for proper virtualization.

10. What's Working Well

✦ Web accessibility maturity

TopBar, SidebarNav, NotificationBell, StripeCheckoutModal, ReactionBar all use ARIA correctly. Keyboard navigation, focus restoration, html lang="es" all solid.

✦ Mobile FormField component

Exemplary a11y: accessibilityLabelledBy, accessibilityHint, accessibilityState, error role="alert" + liveRegion="polite", nativeID linkage. Gold standard pattern.

✦ Mobile inventory screen

79 accessibility props: radiogroup/radio, headers, labels, hints, states. Most thoroughly labeled screen in the codebase.

✦ Web i18n infrastructure

Full i18next with 5 locales, translation files, useTranslation(), locale persistence + backend sync. Strong foundation to port to mobile.

✦ Web currency conversion

Frankfurter API + localStorage caching (24h TTL) + formatMoney() auto-conversion + audit trail. User-centric design.

✦ Web error handling components

ApiErrorNotice with retry, ApiLoadingNotice, EmptyState with icon/title/description/action, PageShell skeletons. Should be used more consistently.

✦ Feature registry architecture

Centralized registry with role-based access, bilingual support, nav group organization, evaluation functions. Used consistently by sidebar and top bar.

✦ Design token alignment

Base palette values match between platforms. 4px spacing base consistent. Border radii nearly identical (2px diff on "md").

✦ Mobile auth screen

Proper a11y: role="tab" + selected state, error role="alert" + liveRegion="assertive", busy state on buttons. Good KeyboardAvoidingView.

✦ Web StripeCheckoutModal

Multi-step form with focus management, error refocusing, useReducer, ARIA, focus restoration. Model for complex forms.
