Blocking finding: one unit-fixture lifecycle gap remains in the reviewed test source.

The live-child test awaits once(child,'message') without a deadline; the descendant test likewise awaits its message and exit promises without deadlines. A node:test test timeout does not settle those arbitrary pending promises, so their finally blocks need not execute while a startup/fixture failure leaves a child alive. The descendant PID is only delivered after its own ready message; if that handshake fails, the test can lack the PID while the parent has already spawned a child. Killing only the parent does not reliably reap that unknown descendant. Explicit bounded readiness/exit waits that reject within the test's outer timeout are required, plus ownership/cleanup of the descendant before that handshake can fail (for example an immediately reported PID and/or a parent fixture TERM handler that terminates and reaps its child).
