# 2026-07-30

- Implemented city-subscription-based event discovery across Ticketmaster,
  Buen Plan Ecuador, and structured venue-owned iCalendar/JSON feeds.
- Event discovery now runs in isolated six-hour provider slots with a PostgreSQL
  leader lock, per-source health/error tracking, a 24-hour circuit-breaker
  cooldown after repeated failures, and a two-run missing-event grace period.
- Added canonical multi-source event matching so ticketing platforms can attach
  separate purchase options without duplicating the public event. Ticketmaster,
  Buen Plan, and venue sources use configurable priorities.
- Added country-aware event-city/subscription APIs and mobile UI. The Events tab
  defaults to subscribed cities, supports Explore-all and saved-event scopes,
  and lets users add/remove global cities by ISO-2 country code.
- Added mobile multi-platform purchase choices to event detail.
- Added strict-admin source management APIs and the HQ page at
  `/configuracion/fuentes-eventos` for enabling providers and registering
  city-bound HTTPS iCalendar/JSON venue feeds.
- Added production migration `2026-07-30_event_city_subscriptions.sql`, registered
  it in the guarded migration manifest, updated schema verification, and rewrote
  the event-discovery operations document.
- Production event discovery must remain disabled until both discovery
  migrations are applied and logs/health are verified. Buen Plan uses a public
  but undocumented endpoint and remains independently disableable.
